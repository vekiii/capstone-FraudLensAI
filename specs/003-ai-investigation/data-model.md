# Data model - feature 003

Status: design, not implemented migrations. Closed machine-readable boundary definitions are in [schemas.json](contracts/schemas.json); provider-only projection differs from local context. IDs are opaque, never paths. No dataset labels are fields in these entities.

## Shared validation rules

Version `contract_version=1` applies to investigation envelopes only; it does not change source v1/v2. Local instants are UTC strings ending Z; comparisons parse instants, not lexical offsets. UUIDs generated by the application form run/attempt/evidence/review IDs (`inv_`, `att_`, `ev_`, `rev_` + 32 lowercase hex digits). Content digests use SHA-256 lowercase 64 hex. JSON hashes use UTF-8, sorted keys, compact separators, no NaN, Decimal stored as original strings; normalized source text replaces CRLF with LF and rejects BOM/bare CR. No trailing-whitespace normalization.

Query length is 1-500 trimmed Unicode characters. Narrative text is 1-2000 characters; human rationale 1-2000 after trim; actor 1-80. Report sections have at most 20 items. Exact amounts are source strings, never binary floating-point conversions. Unknown properties and unsupported enum values are rejected at all boundaries. Schema format checks and semantic identity/access checks are mandatory.

## InvestigationContext

Fields: `contract_version`, `context_revision` (hash of the context excluding itself), `source_mode` fixture|dataset, `case_id`, `snapshot_ref`, `dataset_version` (nullable for fixture), `observed_at`, `source_payload`, `history`.

- `source_payload` is unchanged foundation CaseDetail for fixture or pinned producer CaseDetailV2 for dataset. Fixture snapshot is an application-generated `fixture_<64 hex>` digest binding fixture file and scorer version. It is not called a completed dataset run. Fixture dataset_version is null; dataset version is the producer dv_ identifier.
- Case/transaction/run/dataset equality across wrapper and payload is semantic validation in addition to schema. Reject unknown or mismatched source/context versions, nonfinite scores or changed explanation scales. Preserve raw minute time, assumed UTC, paid/received currencies and exact precision.
- `history`: availability available|unavailable; cutoff UTC or null only when unavailable; coverage full|incomplete|unavailable; start UTC or null; lookback_days exactly 7 for initial adapter; view_scope authored_fixture|synthetic_shared_banks; reason nullable. No event list is embedded here; the HistoryReader returns validated evidence separately. Full coverage is not inferred from an empty result. Dataset cutoff must match assessment cutoff.
- Local payload may contain synthetic account IDs. Outbound projection uses server-owned alias mapping and only explicitly selected fields. V1 does not gain fake banks/UTC basis/coverage. Corresponding missing evidence is reported.

## KnowledgeDocument, CorpusVersion, Passage

Document: doc_id (1-80 safe identifier), title (1-200), origin_kind official|simulated|dataset_guide, source_uri (reviewed source locator or local document ID), published_at (date or null with unknown reason), retrieved_at, jurisdiction, version, reviewed_by/at, reuse_terms, content_sha256, included_sections and applicability_notes. Review names/dates must be real; unreviewed content cannot be published.

CorpusVersion: `corpus_<64 hex>` digest of ordered document/version/hash entries + chunker configuration. Configuration versions include normalization and character limits. Corpus states staged|complete; only complete can be selected. Passage: passage_id hash binding corpus/doc/section/subpassage/text, section label, ordinal, exact text <=2400 characters, content digest, inherited provenance. Active corpus selection never mutates previous evidence.

## EvidenceItem

Fields: evidence_id, attempt_id, context_revision, kind case_fact|history|procedure, local provenance locator, exact payload, content digest, timestamp, source version. Fact evidence exposes typed field/value assertions; history provides permitted ordered events and coverage/truncation. Procedure evidence preserves exact passage text + all applicability metadata. Evidence references are authorized only when they belong to the same attempt or have been explicitly revalidated/copied into a linked retry.

Outbound evidence aliases are scoped to the run; local aliases resolve back to source data. Provider continuation payload is stored separately in a private field; it is never a case explanation, analyst-readable reasoning transcript or evidence of factual support.

## InvestigationRun, Attempt, ToolStep, ProviderDispatch

Run holds run_id, case/context binding, created_at and linked attempts. Attempt holds attempt_id, parent_attempt_id nullable, state, monotonic revision >=1, source/corpus/retrieval/prompt/provider configuration digests, requested/returned model, deadline, counters, controlled failure and immutable reports. Request identity is a UUID supplied per user action, unique with operation and demo actor; same identity/same request returns existing result, changed payload is 409.

ToolStep holds tool call ID, sequence, name, checked arguments, scope binding, status and evidence references. ProviderDispatch holds sequence, reserved_at, outcome pending|completed|unknown|failed, provider_request_id nullable, elapsed, returned model, usage nullable, private continuation item and controlled error. Only returned usage is recorded as known. Budgets are reserved transactionally before sending; rejected tool arguments do not execute but repeated invalid requests still consume provider requests/deadline.

One active worker claim globally, held via transactionally updated lease owner/expiry; lease extends only within 120 s. Before I/O: reserve dispatch count/intent then release lock. After I/O: compare state/revision/lease; late results may be logged privately but cannot publish a report. Claim expiry or restart moves an active attempt to failed/interrupted; explicit retry creates a child attempt with fresh limits and disclosure of unknown spend. Reused evidence must match source context and corpus and be copied/rebound. No automatic redispatch.

## InvestigationReport and AnalystReview

Report contains report_id (content digest), attempt_id, context_revision, `outcome` ready_for_review|needs_information, `summary`, `observed_facts`, `risk_indicators`, `alternative_explanations`, `missing_information`, `recommended_checks`, `limitations`, `citations`, validation status and created_at. Summary is a list of typed claims rather than uncited free prose. Claim has text, kind observation|hypothesis|procedure, evidence_refs, exact_assertions and quotes. Exact assertions bind evidence_ref + field path + exact source string. Quotes bind an evidence_ref + exact substring. Observation claims require case/history evidence; procedure claims require procedure evidence; hypotheses cite premises. Missing-information items do not assert unavailable facts. Unknown referenced fields/citations, mutated exact assertions or nonmatching quotes fail validation. General unsupported prose remains a separate semantic-review risk.

Report content is immutable; corrections create a new linked revision. report_id is SHA-256 of canonical JSON containing attempt_id, context_revision and draft, so identical prose in two attempts does not collide in the report table. The public semantic_review value is derived from separate review records, not a mutation of the original draft or a scientific quality guarantee. Needs-information still persists a structured limitations draft if offered for review. No draft is accepted merely because it matches JSON shape. Store schema/reference checks separately from semantic review, initially not_reviewed.

AnalystReview: review_id, report_id, expected attempt revision, actor from local application settings (not model input), disposition escalate|close|request_more_information, rationale, optional correction note, supersedes_review_id nullable, timestamp. Ready reports allow three dispositions; needs-information allows only request_more_information. Failed/cancelled attempts allow none. Update attempt to reviewed + append review/audit in one CAS transaction. Corrections reference current review/report and increment revision; no deletion/overwrite.

## States and allowed transitions

| From | To | Condition |
|---|---|---|
| created | gathering_evidence | explicit worker claims queued attempt |
| gathering_evidence | drafting | evidence calls complete, enough context to draft |
| gathering_evidence | needs_information | insufficient facts/guidance; saved limitations draft |
| drafting | ready_for_review | schema/reference/exact-value validation passes |
| drafting | needs_information | valid limitations draft cannot support useful recommendation |
| created/gathering_evidence/drafting | failed | budget, interrupted dispatch, provider/validation error or stale source |
| created/gathering_evidence/drafting | cancelled | explicit analyst cancellation, optimistic revision matches |
| ready_for_review/needs_information | reviewed | allowed explicit disposition with rationale |

All other transitions reject. A linked retry does not transition the old terminal attempt. Review corrections stay reviewed with a new immutable review revision. Corpus/context identity never changes within an attempt. Deadline watchdog in worker plus API read reconciliation exposes expiry <=120 s even if transport stalls; hard cancellation bounds the provider await, though billing cannot be guaranteed cancelled.

## Persistence layout (separate SQLite schema v1)

Tables: schema_meta; corpus_versions/documents/passages; investigation_runs/attempts; evidence_items; tool_steps; provider_dispatches; reports; reviews; audit_events; request_keys; worker_lease. Foreign keys bind run/attempt/context/report. Unique (actor, operation, request_key), (attempt_id, sequence), report digest and immutable evidence digest constrain duplicate writes. Busy timeout <=1 second; lock errors become store_busy. Parameterized SQL only; transactions commit atomic state/evidence writes and roll back on failure. Version mismatch refuses writes rather than destructive auto-migration.

## EvaluationPack / EvaluationResult

Public-to-run inputs (case/question IDs) and private reference judgments are separate files/read interfaces. Reference loader exists only in explicit offline evaluation command, not knowledge/tool/provider modules. Manifest hashes bind split/corpus/config/rubric. Results store per-question rank/relevance, no-answer outcomes, claim-level human judgments, missing facts, disagreement, usage/latency/failure denominators and exact artifact versions. They do not enter operational context or retrieval.
