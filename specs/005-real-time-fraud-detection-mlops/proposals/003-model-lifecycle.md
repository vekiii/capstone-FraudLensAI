# ADR 003: Registry metadata with exact-digest live deployment

**Status:** Proposed. **Context:** the existing [artifact loader](../../../backend/src/fraudlens/model_scoring.py) verifies a reviewed local binary, dependency versions, offline dataset/protocol identity and scorer class. An MLflow alias alone cannot satisfy or replace those checks. Original Feature 002 boosted artifact and independent gates are unavailable in this checkout.

**Decision proposed:** SQL/dbt creates immutable point-in-time dataset versions; the existing scikit-learn fit/evaluation flow records parameters, source/feature/label cutoff, metrics and checksums in MLflow. Registry version/alias is discovery metadata. A human-reviewed approval creates a separate deployment record with exact local manifest/model SHA-256, trained dataset/protocol lineage, serving signature and alert policy. Worker loads only that digest through the trusted loader and a strict live adapter; promotion/rollback atomically switches the approved pointer at a batch boundary. Score and alert decision are separately versioned.

**Alternatives:** direct registry alias serving makes mutable alias changes implicit deployment; replacing files in place lacks atomicity/audit; retraining on every stream event mixes labels and serving; retaining only local manifests lacks experiment tracking. **Consequences/risks:** MLflow storage/auth and artifact transfer need governance; model-library versions must match exactly; confirmed labels arrive late and can be selectively sampled; prior IBM test exposure limits claims. **Validation:** T033–T040 dataset manifest, parity, delayed-label freeze, registry round-trip, wrong-digest rejection, manual approval, shadow comparison and rollback tests. No auto-promotion from a metric threshold alone.
