# Proposed trusted live model-serving contract

The existing [trusted loader](../../../backend/src/fraudlens/model_scoring.py) checks local path, manifest/model/metadata SHA-256, protocol and training `dataset_version`, `history-v1`, exact ordered features, dependencies and fitted model class. These checks remain mandatory. Current `ScoreRequestV2`/`ModelScorer.input_row` bind a CSV-derived `dv_...` dataset version to the artifact; a live PostgreSQL event cannot truthfully satisfy that identity. The new contract must use a separate **`LiveScoreRequestV1` → `LivePredictionV1` adapter**, leaving batch v2 unchanged.

Request fields: canonical live transaction (source namespace/ID and event-fact digest), full-coverage ordered snapshot and digest, independent `source_lineage_id`, `generation_id`, event/ingestion time, `feature_version=history-v1`, `serving_contract_version`, approved deployment ID and exact model/manifest digest. The adapter verifies event/snapshot identity, feature policy signature, finite numeric values, categorical types, exact order, preprocessing signature, expected model class and package versions. It calls the train-fitted pipeline; it does **not** refit, synthesize an offline dataset version or accept uploaded joblib. Artifact loading uses the approved artifact's actual *training* dataset/protocol identities, then checks the approved live serving signature separately. Unknown/incompatible artifact or missing approved transfer blocks inference.

Output follows [prediction.schema.json](prediction.schema.json): finite uncalibrated positive-class estimate in [0,1], exact model/feature/source lineage, score time and explanation whose base + displayed contributions + remainder reconstructs the score on its declared scale within the frozen tolerance. A tree path and boosted sequential explanation are model-specific; no causal or calibrated claim. Alert policy is a **different versioned decision** with threshold and optional deterministic daily capacity ordering; changing that policy does not change the score or model identity. A worker pins one approved digest and policy per finalized batch; deployment pointer changes only at a safe boundary. Promotion/rollback records actor, review, old/new digest and effective time. Registry aliases cannot bypass the exact deployment digest.

Compatibility gate: positive and negative contract tests must cover wrong training lineage, live source lineage accidentally substituted for it, hash/dependency mismatch, reordered/missing features, changed currency units, unapproved score scale, wrong model class, stale deployment and explanation reconstruction. Existing `ScoreRequestV2`, fixture and batch tests must still pass. A synthetically fitted adapter test proves mechanics only; it does not approve the boosted candidate or close Feature 002 T065/T066.
