# Proposed PostgreSQL CDC contract

**Producer:** `live_transactions` committed INSERT only. **Transport:** one Debezium PostgreSQL connector/publication/slot → proposed `fraudlens.live-transactions.v1`, one partition, record key `transaction_id`. **Consumer:** one Python worker. No connector/topic is currently configured. See [transaction JSON Schema](transaction-event.schema.json).

Debezium envelope checks: require declared connector name, source database/schema/table, operation `c` (or reviewed initial `r` during a controlled snapshot), non-null `after`, source transaction/LSN metadata and supported schema version. Map `after` to the canonical transaction event, preserving exact decimal strings and UTC event time. CDC capture time/commit LSN are transport metadata; they do not replace business event time. For the initial empty-table demo, propose a no-data snapshot after migrations and before producer inserts. For a nonempty migration, freeze a consistent snapshot and LSN cutover, reconcile counts/digests, then release streaming; never guess a cutover point. Updates, deletes, tombstones, malformed records and unsupported schema revisions are quarantined with redacted reason and offset, not scored. Unknown envelope fields are rejected or explicitly allowlisted by a reviewed mapping revision.

Delivery is at least once. DB `pending_events` and `stream_positions` commit together; Kafka offset acknowledgment follows that commit. On restart seek/reconcile from the durable DB offset, and deduplicate by source ID plus fact digest. Retry transient DB/broker errors with bounded backoff; persist a permanent failure/quarantine decision before advancing a checkpoint. Monitor connector state, slot LSN/WAL retention, broker lag and DLQ growth. The retention/replay horizon is fixed in T002 after resource tests. A lost slot or broker gap is a coverage incident requiring explicit backfill, not an empty-history reset. [Debezium's PostgreSQL connector documentation](https://debezium.io/documentation/reference/connectors/postgresql.html) motivates the slot/snapshot review; exact image/configuration remains unverified locally.
