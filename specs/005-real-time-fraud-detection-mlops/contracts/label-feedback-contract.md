# Proposed confirmed investigation feedback contract

Confirmed outcomes are **separate** from transaction facts, broker inference events, feature state and analyst read APIs. The current IBM synthetic target is a benchmark label, not automatically a confirmed human investigation outcome. A restricted future feedback write boundary accepts `transaction_id`, `outcome` (`confirmed_suspicious`, `confirmed_not_suspicious`, `indeterminate`), `confirmed_at`, `available_at`, reviewer identity, evidence reference and idempotent `label_revision`. It verifies reviewer authority, existing transaction identity, chronological availability and a nonempty evidence reference. Revisions append; no silent overwrite. Store encrypted/role-restricted in `confirmed_labels`; expose only aggregate, de-identified delayed evaluation where allowed.

Offline training/evaluation selects the latest authorized confirmed revision whose `available_at` is **before the frozen label cutoff**, with a fixed observation/evaluation period. Indeterminate/unconfirmed outcomes are excluded from binary metrics but included in coverage counts. Keep labels out of live CDC topic, `LiveScoreRequestV1`, feature payload, prediction record and retriever/API responses. Log source lineage, cutoff, revision counts and role of labels in MLflow; freeze predictions before joining labels. Never describe delayed, selected investigation outcomes as an unbiased population without a sampling/selection-bias analysis. Tests must prove a label edit cannot change feature digests or stored scores and that a later label cannot leak into an earlier training dataset.
