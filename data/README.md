# Data and Git policy

Track small, reviewed, synthetic fixtures under `data/fixtures/` when later tasks
create them. Do not put real customer/account data, ground-truth evaluation labels,
credentials or large datasets into application fixtures or evidence logs. Phase 1
creates no datasets or fixture records.

## T014 synthetic case fixtures

`fixtures/cases.json` now contains exactly three entirely invented transfers:
CASE-001/TX-001, CASE-002/TX-002 and CASE-003/TX-003, ordered by case_id.
Account strings beginning DEMO-BANK- and containing SYN-ACCOUNT- are fictional
bank-qualified references, not real banks, IBANs or customer identifiers.
Amounts and UTC timestamps are illustrative; no real transaction source was used.

The storage format is a JSON array of closed `{case_id, transaction}` records.
Transaction fields are those in the canonical Transaction contract. No labels,
scores, assessment objects, model claims or evaluation metrics are stored.
`fraudlens.cases.load_cases` validates the records, rejects duplicate case and
transaction IDs, and returns fresh records sorted by case_id. Injected empty
arrays are valid for empty-state tests; the shipped file itself has three cases.
See [T014 evidence](../evidence/tasks/T014.md) for validation results.

`data/raw/` and `data/processed/` are local ignored locations for downloaded inputs
and generated transformations. Later data work should record source, acquisition
date, license, version/hash, transformation and split definitions in reviewed
metadata so another member can reproduce it without committing the data. Keep
evaluation labels and reference answers outside prediction/retrieval inputs; do
not tune against final holdout data.

Local generated evaluation output goes in ignored `evals/results/`. Reviewed small
evaluation definitions/datasets elsewhere under evals/ may be tracked after review;
place concise sanitized conclusions and actual execution in evidence/tasks/.
Fixture tests are not ML evaluation. No evaluation output is generated by setup.

## Feature 002: IBM AML data and generated outputs

The Feature 002 source, processed snapshots, model artifacts, and evaluation
outputs are local-only and must not be committed. Use `data/raw/` for the acquired
`HI-Small_Trans.csv`, `data/processed/` for validated canonical data/features and
manifests, `data/artifacts/` for frozen model/preprocessing artifacts and metadata,
and `data/eval/` for generated predictions and evaluation outputs. The root
`artifacts/` directory is reserved for temporary generated/test scratch. These
paths are ignored by the repository `.gitignore`; `evals/results/` remains the
existing location for generated evaluation output from other work. Do not place
credentials, source rows, record-level labels, or hidden holdout answers in Git or
evidence.

Before ingestion, verify the exact source/revision, current license terms, file
checksum, CSV schema and duplicate `Account` positions. The IBM README identifies
the data license separately from the repository-code license; capture the source
and data license in a data card. The importer must keep source and processed counts,
rejections, warm-up and scoreable counts separate. Store restricted label audits
and record-level evaluation artifacts only in ignored local paths, and log query
shape/authorization in sanitized evidence without copying labels or rows. Record
source/checkpoint/output hashes and processing configuration in the manifest.

## Feature 002 T203 source verification (partial)

The local `raw/HI-Small_Trans.csv` was verified on 2026-11-18 by hashing its
bytes, checking its header, and streaming the ten non-label columns. The final
label field was discarded before CSV parsing; no label values were inspected,
stored, counted, or displayed. The file is 475,664,283 bytes, has SHA-256
`b19d39f515523373f991b689c07e11e7b0b95c17a2c27a87d91584ae16c5b040`, and its
header is exactly:

```text
Timestamp,From Bank,Account,To Bank,Account,Amount Received,Receiving Currency,Amount Paid,Payment Currency,Payment Format,Is Laundering
```

The file contains 5,078,345 records; all had ten non-label fields in this scan.
Observed lexical shapes across those fields: `Timestamp` was consistently
`YYYY/MM/DD HH:MM`; both bank fields and amount fields were numeric text; the two
`Account` fields contained both numeric-looking and nonnumeric text; currencies
and `Payment Format` were nonnumeric text. These are lexical observations, not
inferred pandas/database dtypes, and IDs must remain strings. The label column was
not classified. The exact format contained no timezone/offset marker.

The duplicate positions in this file are zero-based: `From Bank` 1 + first
`Account` 2, and `To Bank` 3 + second `Account` 4. This confirms the local
header-order hypothesis and file fingerprint in the Feature 002 spec. The file's
filesystem modification time is 2026-11-13 15:51:53 UTC; this is not an
acquisition timestamp and does not identify a Kaggle dataset version. The exact
Kaggle version/revision remains unpinned and must be recorded from the download
source before ingestion can be called reproducible.

IBM's [AML-Data README](https://github.com/IBM/AML-Data/blob/main/README.md)
states that the repository code is Apache-2.0 while the actual dataset is under
[CDLA-Sharing-1.0](https://cdla.dev/sharing-1-0/), and links to the Kaggle
distribution and an IBM Box PDF. The README describes the data as synthetic.
The CDLA text permits use and publication subject to its conditions; publication
of data or enhanced data carries license, attribution and change-notice duties.
No source or processed data is published from this repository. The current
Kaggle listing's own license/terms field still needs capture for the selected
release before real ingestion or any sharing decision.
The Kaggle listing and Box PDF could not be read in this verification, so the
current Kaggle-specific terms and any release-specific details remain unverified.
Review the CDLA terms before publishing source or enhanced data.

The local scan establishes observed non-label lexical shapes, but not authoritative
field types. IBM's accessible README and linked NeurIPS paper do not specify the
timezone for this release. The subsequent project UTC assumption is recorded
below and in the protocol; it is not a source-system claim. For parsing, retain
all raw CSV fields as text initially; identifier preservation and amount/label
validation remain later pipeline work.
See [T203 evidence](../evidence/tasks/T203.md) for source links, checks and
limitations. The later explicit local-copy decision below closes T203 for the
measured source bytes despite the unavailable upstream release/acquisition
record and Kaggle listing terms. Publisher-declared field types and timezone
remain undocumented; the text-first and conditional time policies record how
the project handles those limits.

A 2026-11-19 follow-up confirmed that IBM/AMLSim is a separate generator whose
schema does not describe this CSV. A third-party copy carries the same file hash
and size, which corroborates byte identity but does not establish the local
file's Kaggle version or acquisition history. The Kaggle listing/API and browser
remained unavailable, so no version number or Kaggle-specific terms were inferred.
The user subsequently confirmed a local download but could not provide its
version or receipt. They then explicitly directed closure of T203 and execution
of T210. The [protocol's local-copy exception](../specs/002-data-and-risk-scoring/protocol.md#t203-local-copy-decision-and-t210-scope)
pins this copy by measured SHA-256 for local canonical preparation. Its Kaggle
revision, acquisition date and Kaggle listing terms remain unknown. T203 is
closed under that exception; it does not establish redistribution rights or
authorize model claims.

The user-supplied Kaggle description excerpt identifies `HI-Small_Trans.csv` as
the HI-Small transaction file and `HI-Small_Patterns.txt` as a separate pattern
file. The six HI/LI size variants are independent. For HI-Small, the publisher
describes approximately five million transactions, 515,000 bank accounts and
5,100 laundering-tagged transactions, with primary activity Sep 1–10, 2022.
It also warns that some transactions occur later and describes those as
laundering. These are approximate publisher statements, not measured local
counts or an authorized label audit. The dataset shows an entire synthetic
financial ecosystem, which is broader than one real bank's view. The publisher's
60/20/20 split suggestion does not replace Feature 002's specified boundaries.
The excerpt has no version, license sidebar, declared dtypes or timezone.

The [Feature 002 protocol](../specs/002-data-and-risk-scoring/protocol.md)
now records a project assumption to interpret naive timestamps as UTC at minute
precision for later temporal processing. No source document checked so far
asserts that timezone, and contrary documentation for the pinned release would
stop ingestion. Initial parsing continues to preserve the timestamp text.
