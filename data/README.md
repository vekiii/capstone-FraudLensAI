# Data and Git policy

## Feature 002 local import

Follow the [executable quickstart](../specs/002-data-and-risk-scoring/quickstart.md)
to build a local SQLite database from an authorized copy of the IBM v8 CSV.
Each teammate can create their own database from the same hash-matched CSV;
both files remain ignored and local. The CLI checks the separate team approval
for the exact mapping, source and namespace. `inspect` keeps its read-only
pending-configuration behavior.

Feature 002 Prompt 1 historically prepared [ibm_hi_small_v1.json](mappings/ibm_hi_small_v1.json)
with `pending_team_review` and `import_allowed=false` flags. The later collective
approval is recorded outside the hash-approved mapping; the local import CLI now
consumes it for the exact IBM v8 source binding. It records an approved synthetic
UTC+00 analysis assumption, not a source timezone fact. The read-only inspector
still reports the historical flags. Original CSV and the separate downloaded
reference remain ignored under data/raw/; no raw labels/rows are tracked. See
[technical resolution](../evidence/tasks/feature-002-technical-resolution.md).

Track small, reviewed, synthetic fixtures under `data/fixtures/` when later tasks
create them. Do not put real customer/account data, ground-truth evaluation labels,
credentials or large datasets into application fixtures or evidence logs. Phase 1
creates no datasets or fixture records.

## T014 synthetic case fixtures

`fixtures/cases.json` now contains exactly three entirely invented transfers:
CASE-001/TX-001, CASE-002/TX-002 and CASE-003/TX-003, ordered by case_id.
Account strings beginning DEMO-BANK- and containing SYN-ACCOUNT- are fictional
bank-qualified references, not real banks, IBANs or customer identifiers.
Amounts and UTC timestamps are illustrative; no real transaction source was used.

The storage format is a JSON array of closed `{case_id, transaction}` records.
Transaction fields are those in the canonical Transaction contract. No labels,
scores, assessment objects, model claims or evaluation metrics are stored.
`fraudlens.cases.load_cases` validates the records, rejects duplicate case and
transaction IDs, and returns fresh records sorted by case_id. Injected empty
arrays are valid for empty-state tests; the shipped file itself has three cases.
See [T014 evidence](../evidence/tasks/T014.md) for validation results.

`data/raw/` and `data/processed/` are local ignored locations for downloaded inputs
and generated transformations. Later data work should record source, acquisition
date, license, version/hash, transformation and split definitions in reviewed
metadata so another member can reproduce it without committing the data. Keep
evaluation labels and reference answers outside prediction/retrieval inputs; do
not tune against final holdout data.

Local generated evaluation output goes in ignored `evals/results/`. Reviewed small
evaluation definitions/datasets elsewhere under evals/ may be tracked after review;
place concise sanitized conclusions and actual execution in evidence/tasks/.
Fixture tests are not ML evaluation. No evaluation output is generated by setup.

The root .gitignore preserves the existing course PDF exclusion and adds local
venvs, dependency folders, downloaded tools/caches, dist/build output, Python/lint/
test/coverage output and local `.env` / `.env.*` files. A reviewed `.env.example`
may be tracked, containing placeholders only. Never force-add sensitive files.
Ignored data must also be checked before adding: ignore rules do not untrack a
previously committed file.

Keep uv.lock and frontend/package-lock.json, specifications, prompts, evidence,
small reviewed fixtures, `.agents/skills/` and shared `.specify/` content in Git.
Honor `.specify/.gitignore` for local feature.json, extension overrides and adapter
package state. Do not blanket-ignore either shared directory. No commit, push,
merge or deployment is part of this setup task.
