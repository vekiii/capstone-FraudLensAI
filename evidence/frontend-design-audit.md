### Verified inconsistencies and gaps

1. **Simulation has no page-specific styling.** `web/src/pages/Simulation.tsx:11` renders `.simulation-page`; `web/src/simulation.ts:163-194,262-355` creates forms, disclosures and tables. Neither `web/src/styles/tokens.css` nor `web/src/styles/site.css` defines `.simulation-page`, `.simulation-settings`, `.simulation-ordering`, or `.simulation-recipe-file`. The global header is fixed (`site.css:11`). **Inference:** the page begins under the header and its wide tables may overflow on narrow screens. Rendering at 320/768/1440 px is needed to confirm exact severity.
2. **The operational surfaces have less visual structure than the showcase.** `web/src/investigation/views.ts:42-122` creates a report, history, trace, claims, evidence buttons, and decision form mostly as bare elements; `web/src/styles/site.css:139-144` provides only broad spacing/field rules. `web/src/pages/Cases.tsx:170` uses `.synthetic-notice`, but no matching selector exists. `web/src/scoring/views.ts:24-27,199-220` emits `.message` and `.app-header` without matching selectors. This is a verified selector coverage gap; the exact rendered impact needs a browser check.
3. **Focus treatment is uneven.** `web/src/styles/site.css:6` styles links/buttons, and lines 238/242/253 style selected input/link/summary cases. There is no shared `:focus-visible` rule for all `input`, `select`, `textarea`, `summary`, and file controls generated in `web/src/investigation/views.ts:49-62` and `web/src/simulation.ts:316-345`. Browser default outlines may still appear; consistency and visibility must be checked in keyboard QA.
4. **Some small metadata is hard to read by token calculation.** `--dim: #687078` on `--bg: #0b0b0c` in `web/src/styles/tokens.css:3,7` yields about **3.91:1** contrast for text. `web/src/styles/site.css:29-30,78,114-123` applies dim to 10–11 px metadata and labels. This is below the common 4.5:1 normal-text target on the base background. Actual contrast on translucent panels needs separate measurement.
5. **Navigation and language are split across contexts.** `web/index.html:2` declares English, while `web/src/pages/Cases.tsx`, `web/src/scoring/views.ts`, and `web/src/investigation/views.ts` contain substantial Serbian text. Only `web/src/pages/Simulation.tsx:11` explicitly sets `lang="sr-Latn"`. `web/src/components/SiteFrame.tsx:10-18` does not link to the `/model-cases` route declared in `web/src/AppRoutes.tsx:29`, and its “Live demo” link leads to the explicitly illustrative page in `web/src/pages/Live.tsx:9-11`. The model-cases route is intentionally reachable from scoring (`web/src/scoring/views.ts:90-96`); do not assume it should become a main-nav item. No skip link exists before the seven-link fixed header in `SiteFrame.tsx:30-36`.
6. **Showcase and active workflow copy need clearer boundaries.** `web/src/pages/Rag.tsx:9-11` calls retrieval proposed and inactive *in this preview*, whereas `web/src/pages/InvestigationPanel.tsx:11-19` loads an actual investigation controller in Cases. `web/src/pages/Live.tsx:9-11` is correctly labelled illustrative, but the nav name “Live demo” can imply the active workflow lives there. `web/src/pages/Overview.tsx:12,18` says “FEATURE 005 / IN PROGRESS” and “Every second, millions swipe”; the latter is a payment-card image in an AML transaction product and has no cited source in the repository. These are verified copy differences; product owners should confirm the desired current status before changing any claim.
7. **Showcase metric placeholders are intentionally separated from measured output.** `web/public/data/metrics.json` and `web/public/data/eda.json` explicitly say `not_yet_measured`, and `web/src/pages/Overview.tsx:29` / `web/src/pages/Data.tsx:16-18` render that status. This is not evidence that the backend lacks model results: `web/src/scoring/views.ts:98-151` has an authorized aggregate-results view. Treat the page distinction as a content/navigation issue, not a license to replace placeholders with invented metrics.
8. **Some labels are decorative rather than informational.** `web/src/components/Atoms.tsx:7` adds “FIELD NOTES” to every `SectionTitle`; `web/src/pages/Overview.tsx:18-19` uses cinematic story beats before the concrete product explanation. These are not functional defects. Under the external skill’s content rule, review whether each line earns its space on an evidence product.

## 2. Apply the external skill without changing product identity

The [skill](https://github.com/Ilm-Alan/frontend-design/blob/main/SKILL.md) asks for context, one strict aesthetic anchor, a visible differentiator, exact token fidelity, and truthful on-screen content. Its [README](https://github.com/Ilm-Alan/frontend-design/blob/main/README.md) summarizes eight anchors. **Industrial is the closest reference** for the dark surface, signal lime, thin rules, and data density. Adopting it literally would require mono type everywhere, pitch black, flat surfaces, and removal of rounded badges, the current sans display, backdrop, and editorial sections. That would materially replace FraudLens’s existing identity. Swiss would require a white surface, so it is also unsuitable as a full conversion.

Recommended direction: retain the **dark editorial evidence workspace** already encoded in `tokens.css` and `site.css`. Apply the skill’s useful principles selectively: deliberate token use, one clear hierarchy per view, a visible evidence/provenance motif, content that names real states, and standard labels for standard actions. The existing differentiator can be the **traceable path from score to source to human decision** (`Overview.tsx:35-39`, `Cases.tsx:39-112`, `investigation/views.ts:111-122`). Sharpen that path; do not invent a new visual gimmick or claim strict compliance with any anchor.

## 4. What not to change

- Keep the FraudLens wordmark, near-black/lime palette, sans display with mono metadata, hairline/grid language, and shared `SiteFrame`/`Atoms` architecture (`web/src/styles/tokens.css`, `web/src/styles/site.css`, `web/src/components/`).
- Keep the existing reduced-motion, low-power and WebGL fallbacks (`web/src/motion/`, `web/src/webgl/Backdrop.tsx`); any future motion edit must preserve them.
- Keep fixture/model/source badges, “not measured” states, synthetic-data warnings, evaluation limits, evidence references and human decision text (`web/src/pages/`, `web/src/scoring/views.ts`, `web/src/investigation/views.ts`, `web/public/data/`).
- Keep API decoders, snapshot identity, request cancellation, review/decision rules, simulation calculations, route contracts, and backend boundaries (`web/src/api.ts`, `web/src/contracts.ts`, `web/src/investigation/`, `web/src/scoring/`, `web/src/simulation.ts`). Design work may add presentation hooks, but must not alter data semantics.
- Keep tables and disclosures where they convey real denominators, units, provenance or detailed results. Improve their presentation without replacing them with decorative charts.

## 5. Avoid

Avoid a wholesale anchor conversion, a new font/dependency or component framework, generic glowing “AI dashboard” styling, extra animations/parallax, fabricated metrics or personas, copying the external skill’s sample content, weakening provenance labels, and any backend/model/RAG behavior change. Do not treat the showcase’s intentionally illustrative JSON as live results. Do not expand the MVP or alter human authority. Do not redesign a route because it differs visually until its actual purpose and rendered problem are verified.
