## Decision and code

The latest user instruction explicitly puts the three baselines in T223, superseding the earlier task sequencing that put LightGBM first. The spec, plan and task wording now reflect that sequence. The eight frozen LightGBM candidates remain the next model implementation and the only current-phase selection family; five HistGradientBoosting comparisons remain later T224 work. The old T221 JSON retains its original `implementation_order` metadata and hash as an historical choice record; the later explicit T223 instruction is the sequence amendment. No cross-family selection or real fit is authorized by this change.

[boundaries.py](../../backend/src/fraudlens/training/boundaries.py) validates all four partitions and rejects any extra field, including a label, before invoking the label reader. It fits sorted currency and format vocabularies on train rows only, adds a reserved unknown bucket, preserves the eleven-field order and exact Decimal historical sums until finite float64 one-hot conversion at the model boundary. It requests only train and validation labels; test and showcase view types have no labels attribute. This is a finite synthetic preparation boundary, not a full-size streaming feature publication path.

[baselines.py](../../backend/src/fraudlens/training/baselines.py) fits a train-prevalence constant, a depth-5/min-leaf-500 decision tree, and L2 logistic regression. Tree and logistic weights are `{0: 1, 1: train_negative_count / train_positive_count}`; the constant is unweighted. The logistic numeric scaler fits on train only. Scikit-learn 1.9.1 expresses L2 with `l1_ratio=0.0`, avoiding the deprecated `penalty='l2'` argument while keeping the frozen L2 behavior. All estimator fits use train labels only; one-class train data is rejected.
