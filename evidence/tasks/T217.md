## Implementation and limits

`LabelAuditService` takes a frozen identity-to-partition map and finite local records. It validates identities, UTC-aware instants, eligibility and partitions without reading labels. Only the exact `pretraining_class_audit` purpose and three unfiltered aggregate shapes are allowed: scoreable development UTC-day counts/positives, train/validation/test scoreable totals, and one showcase-wide source/scoreable/positive total. It rejects record-level and filtered queries before label reads. Exact integer or canonical text `0`/`1` label encoding is required for permitted aggregation; booleans, floats and other spellings fail.

Every attempted query appends a UTC time, purpose, bounded query description and result (`allowed`, `denied` or `error`) to JSONL using append mode and `fsync`. A result is returned only after logging succeeds. The showcase-wide total is single-use across service instances sharing the log path. The log omits label values and transaction IDs. It is append-only by application behavior, not tamper-evident or cross-process serialized. A malformed existing log stops showcase access. Real ingestion, partition hash binding, resource measurement, FR-018 prevalence tolerance assessment and actual class audit remain T218/T219 work. This implementation does not grant record-level training/evaluation label access.
