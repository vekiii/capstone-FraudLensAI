## Implementation

Added `backend/src/fraudlens/data/pipeline.py` and `manifest.py`. `run_pipeline` validates finite input in configured chunks and writes each chunk as a deterministic staged JSON checkpoint. Each checkpoint binds the source hash, config hash, chunk order, input-prefix hash, output hash, and reconciled source/accepted/rejected counts. Resume is explicit: it verifies staged chunk hashes and metadata, replays and hashes each source prefix, then appends only new chunks. A source/config mismatch, missing/corrupt chunk, row-count mismatch, or low disk reserve stops the run.

Available disk is checked before consuming input, before each staged chunk, and on the output volume before publication. Final accepted/rejection JSONL files are streamed from staged chunks, hashed incrementally, and bound into `manifest.json`. The manifest contains source/config hashes, separate source/accepted/rejected counts, rejection-code counts, checkpoint/output checksums, and explicit `null`/incomplete provenance and temporal fields where T203/T210 evidence or later temporal processing is required. `COMPLETE` contains the manifest checksum, and the temporary snapshot directory is published by same-volume atomic rename. `verify_completed_snapshot` validates its marker, counts, output sizes, and hashes before use.

The pipeline returns count-only `PipelineResult`; dataset rows and rejections remain in the completed snapshot rather than accumulating in the return value. Disk and chunk sizes are controlled by caller-supplied settings; final safe resource ceilings remain for T209.
