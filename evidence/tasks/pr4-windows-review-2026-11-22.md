## Code review findings

1. **Windows publication fails at activation.** [Publisher](../../backend/src/fraudlens/bridge_publish.py#L164) leaves the SQLite connection open when it reaches `os.replace(stage, destination)`. The transaction context manager commits or rolls back and leaves the connection open. A direct synthetic call to `publish()` (substituting snapshot verifier, scorer and frozen input digests for one authored row) reached activation and raised WinError 5 on Python 3.14.10. The final directory was absent. The staged data contained no synthetic label canary. A smaller Windows probe also observed WinError 5 before closing SQLite, followed by a successful rename after closing. The real transferred snapshot was consumed as published and was never regenerated in this run.
2. **Independent manifest pin is absent at runtime.** [BridgeReader](../../backend/src/fraudlens/bridge_reader.py#L41) matches the manifest with the sibling `COMPLETE` marker and the SQLite files with digests inside that manifest. Both app entry points use this reader. The external digest verification performed for this reproduction covers the received publication. The application still needs a trusted expected manifest digest from outside the publication directory.
3. **Direct publisher regression and Windows reader fixture fix.** The checked-in bridge tests exercise the contract and reading a prebuilt database and have no direct publisher invocation. The direct synthetic probe above exposes the gap. Separately, [the Windows reader test](../../backend/tests/integration/test_model_case_bridge_reader.py#L159) holds a fixture SQLite writer open while it unlinks the file and fails with WinError 32. The read-only consumer explicitly closes its own connections. The frozen pipeline quickstart should state the exact Python patch level.
