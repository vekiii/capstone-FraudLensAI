## Runtime and test design

Python 3.14.7 in the repository's `.venv`; uv 0.10.9, Node 24.20.0, npm 11.19.0.
Dependencies remain those in `uv.lock` and `frontend/package-lock.json`.
`backend/tests/unit/test_scoring_boundary.py` contains a structural test-only
`RulesScorer` with no inheritance from the production scorer. It returns the
illustrative constant 0.23, source=rules and scorer_version=test-rules-v1.
This is deliberately not a proposed production AML rule.

Nineteen scenarios cover:
- The same ordered three cases and unchanged transactions with a new score/source,
  list/detail agreement, canonical JSON Schema validation and preserved metadata.
- Valid rules scores at both 0 and 1 through list and detail delivery.
- Negative, above-one, NaN and positive/negative infinity values through both paths.
- A valid assessment ID belonging to another transaction and adapter exceptions.
- Failure on TX-002 after a valid TX-001 assessment: list delivery raises instead
  of returning partial success or substituting a fixture score.
- Per-test checks that shipped fixture bytes are unchanged; default fixture scoring
  remains isolated from the injected adapter.

Invalid-output doubles use unchecked `model_copy(update=...)` intentionally, so
delivery must revalidate the returned instance rather than relying on constructor
validation inside the adapter.
