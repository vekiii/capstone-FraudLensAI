## Method and environment

`T209-benchmark.py` yields only invented mappings that match the current canonical validator. The wide case gives each generated row a distinct account; the hot case rotates through eight accounts. It uses fixed-width identifiers, 11 source fields including a synthetic `0` label, 10,000-row chunks, the T208 staging/publishing path, and `verify_completed_snapshot`. It reports only aggregate counts, peak process working set from Windows `GetProcessMemoryInfo`, elapsed wall time including snapshot verification, and stage/output byte sizes. It deletes its own temporary ignored directory after each run; pre-existing `data/processed/` content was not modified. These probes are resource measurements, not real-data quality checks or model evaluation.

Runtime: Python 3.14.10 on Windows 11 `10.0.26300-SP0`, local `.venv`; no new dependency installed. The source hash and configuration hash in the probe are synthetic constants. The measured volume had approximately 73.7 GB free at start. The volume is inside the repository's OneDrive workspace, so sync and other machine load may affect elapsed time.

## Frozen preparation controls

- Chunk size and checkpoint cadence: 10,000 source rows; one verified checkpoint per complete chunk and the last partial chunk.
- Process peak working-set ceiling: 512 MiB, an operational stop threshold. The runner does not yet enforce an RSS limit.
- Disk reserve: 10 GiB free on each relevant volume, passed as `min_free_bytes=10737418240`; require at least 20 GiB free before start. The runner checks reserve but does not forecast final output size.
- Runtime ceiling: 15 minutes for approximately 5.1 million canonical rows on this workstation, an operational stop threshold. The runner has no built-in timeout.
- Do not enlarge chunks or proceed after a ceiling breach without a new benchmark/review. The resource settings cover canonical staging and publication only; later temporal sorting/features/model work needs separate measurements.

The 5.1-million-row runtime leaves about 2.7× headroom to the 15-minute ceiling; the observed peak working set is about 0.16× the 512 MiB ceiling. The 20 GiB start threshold exceeds the observed stage-plus-snapshot footprint and preserves the 10 GiB reserve with more than 4 GiB margin. These are local observations and operational limits, not a guarantee for a different source width, volume or workstation.
