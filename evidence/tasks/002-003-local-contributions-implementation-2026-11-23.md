## Scope and implementation

- [Calculation](../../backend/src/fraudlens/scoring/local_contributions.py) reuses the trusted frozen `ModelScorer`, same preprocessor and 140 trees for score/raw/pred_contrib. The 32 ordered matrix columns are mapped to 11 source fields; every one-hot bucket contributes to its source group, including inactive buckets. The native final pred_contrib entry is the base. Amount `current_amount_paid_log1p` is a transformed feature, not source money.
- [Builder and reader](../../backend/src/fraudlens/investigation/contribution_sidecar.py) construct bounded top-three/remainder sidecars, accept only the separate external bundle SHA-256 pin, verify model/manifest/order IDs, both transaction IDs, case/run/dataset/feature/context/feature-snapshot IDs, method/scale/objective, finite values, additive and sigmoid reconstruction, score parity and content digest. Missing configuration or row is `unavailable`; bad pin/content/binding is `invalid`. The existing `/risk` score is never computed from this reader.
- [One-time builder](build_local_contribution_sidecars.py) streamed all three T219 label-free partitions, checked their manifest hashes, selected exactly the 65 published bridge IDs and wrote only ignored `data/processed/local-contributions-v1/sidecars.json` and `full-calculations.json`. It uses exclusive creation, so a repeat cannot silently overwrite the local bundle. Bundle: **111,678 bytes**, SHA-256 `8edb466a84a186f6115b725d10796c409d1aa5fa065ddfddf0e2e3e1beb12429`. Full calculation SHA-256 `36fbb022b8b7db8b5e15fd7401d08e51483689aab6e180367726e126ed003edb`. The pin is supplied through `INVESTIGATION_LOCAL_CONTRIBUTION_SHA256`, outside the bundle; the path through `INVESTIGATION_LOCAL_CONTRIBUTION_PATH`. Both are required with the bridge settings. Without them, the old investigation path remains active.
- [Separate endpoint](../../backend/src/fraudlens/bridge_api.py) returns v1 available/unavailable/invalid state; the published v2 detail route and bridge database are unchanged. [Workflow](../../backend/src/fraudlens/investigation/workflow.py) binds the verified sidecar to a newly created attempt, rechecks before worker use, and joins it only after v2 context validation. [Tools](../../backend/src/fraudlens/investigation/tools.py) save a distinct `case_fact` evidence item whose exact facts contain `local_contribution_v1.*`; its existing `attempt_id`, `context_revision` and `content_sha256` bind the evidence. Saved case/history text retains the full original JSON after a short prefix. Provider projection sends the prefix once and all exact facts; procedure passages remain complete. Existing 16,000-byte tool and 48,000-byte provider gates remain. A replaced pin does not mutate archived evidence/report; reuse retry with a changed sidecar fails stale, and a fresh retry binds the current verified state.
- A retry regression exposed that the old v4 revalidator instantiated fixture history rather than the dataset reader. For sidecar-bound retries only, it now uses the same dataset reader as the original attempt. The new test first failed with `stale_snapshot` for unchanged history, then passed; old retry behavior remains covered by the full regression.
- [Separate React decoder/view](../../web/src/scoring/localContributions.ts) and [case component](../../web/src/pages/LocalContributions.tsx) show method, log-odds, signed direction, top three, remainder, unavailable/invalid and retry. Historical v2 `unsupported_method` is labeled as the **published v2 assessment**; the separate local sidecar has its own heading. The existing v2 decoder/schema were not widened. The test provider's canned limitation was corrected to describe a present local log-odds sidecar, while old saved reports remain immutable.
