## Contract and correction

Implemented `normalize_timestamp_utc`, `build_temporal_features` and `iter_temporal_features_ordered` in `backend/src/fraudlens/data/features.py` under `hi-small-temporal-v1`. Naive source-minute text uses the frozen conditional UTC convention; explicit ISO offsets normalize to aware UTC without losing seconds/microseconds. Invalid or ambiguous timestamp text rejects. The finite-batch helper sorts synthetic rows by UTC instant/source row number. The ordered iterator uses a rolling 24-hour state and rejects out-of-order input; an external sort/checkpoint pass for millions of real rows is not part of this task or authorized by the T212 protocol.

For each timestamp group, the kernel first calculates **all** history/current values from strictly earlier state, then adds all group members. State expires only events **older** than `t−24h`, so the exact lower edge is included. Bank-qualified sender/receiver keys and side-specific currency counts/sums remain separate. Counts are integers; sums use Decimal precision 38 with inexact/rounded traps, and the log1p current feature uses the explicit frozen float conversion. Outputs have the exact eleven-field order, score eligibility, source/time metadata and no label field. Categorical vocabulary fitting and unseen-value mapping remain training-only later work; this kernel preserves valid exact category text and rejects the reserved bucket token.

The original T211 test incorrectly expected the exact 24-hour lower edge to be **excluded**, contrary to FR-012 and the frozen `[t−24h,t)` interval. Corrected that assertion to include the exact edge and exclude an event one minute older. The T211 warm-up test made the same lower-edge count error and was corrected. This was a test defect, not a protocol change. Added regression cases for the current-feature tail, label exclusion, invalid timestamps, source decimal precision, reserved category tokens, required fields and ordered-stream behavior.
