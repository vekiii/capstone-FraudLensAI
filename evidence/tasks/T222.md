## Artifact format and security decision

For the **first LightGBM path**, use LightGBM's native text `Booster.save_model()` / `Booster(model_file=...)` format, with a separate versioned JSON manifest. Before constructing a Booster, the later T227 loader must resolve a path within the configured trusted local artifact root, verify the model bytes against the manifest's independently retained SHA-256, enforce declared feature order/version, protocol/source hashes and locked LightGBM/runtime versions, and fail closed on absent or mismatched files. A matching hash does not by itself make an attacker-controlled manifest or file trusted. Runtime never downloads or trains an artifact. This is a format decision, not an implemented loader or a claim that native model parsing is safe for untrusted input.

For scikit-learn comparison models, persistence is deferred until one is selected for serving. `skops.io` permits inspection and explicit trust of object types but does not support every type and still requires compatible library versions; ONNX avoids a Python estimator at runtime but needs a verified converter and supported model. `pickle`/`joblib` loading can execute code and is excluded from untrusted input. This keeps the first LightGBM runtime path independent of speculative scikit-learn serialization. The [scikit-learn persistence guide](https://scikit-learn.org/stable/model_persistence.html) documents those tradeoffs; [LightGBM's Python guide](https://lightgbm.readthedocs.io/en/stable/Python-Intro.html) documents its native save/load path. The [LightGBM 4.7.0 wheel](https://pypi.org/project/lightgbm/) is published for Windows x86-64; the actual local locked install and roundtrip above establish compatibility on this interpreter.
