then restarted the documented backend and requested the same URL again.
Observed outage HTTP **502**, recovery HTTP **200** with three cases.
This proves proxy outage/recovery, not clicking Retry in a real browser.

- Initial PowerShell probe expected 500 specifically; it printed 502 and exited 1.
  This was an overly narrow probe expectation, not a backend-contract failure.
- A second PowerShell probe accepted 5xx but included Get-NetTCPConnection diagnostics;
  it printed 502 yet exited 1 with no listener listing. It is not counted as PASS.
- A standalone Node probe later confirmed the outage with exit 0:

```powershell
node -e "fetch('http://127.0.0.1:5173/api/cases').then(r => { console.log('Backend stopped, proxy HTTP', r.status); if (r.status < 500 || r.status > 599) process.exitCode = 1; }).catch(() => { console.log('Unexpected proxy connection failure'); process.exitCode = 1; })"
```

Recovery command (exit 0) used Invoke-WebRequest to
http://127.0.0.1:5173/api/cases, ConvertFrom-Json, and assertions for HTTP 200 /
items.Count=3. Vite's expected development terminal ECONNREFUSED logs during outage
are not browser console observations. No raw Vite error was asserted as a valid
backend envelope; the frontend rejects invalid gateway responses as controlled errors.
