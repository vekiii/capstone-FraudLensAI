## Public boundary and validation

- `getCases(options?: RequestOptions): Promise<CaseList>` uses GET /api/cases.
- `getCase(caseId: string, options?: RequestOptions): Promise<CaseDetail>` uses
  GET /api/cases/{encoded caseId} and checks the returned case ID against selection.
- `RequestOptions.signal?: AbortSignal` supports caller cancellation.
- `ApiError` extends Error with typed code and optional numeric status. Codes:
  case_not_found, invalid_request, internal_error, invalid_response, network_error,
  timeout, cancelled. Controlled Serbian messages contain no raw server, parser,
  network or caller-abort text. No implicit retries or fallback records.
- contracts.ts exports Transaction, RiskAssessment, CaseSummary, CaseDetail,
  CaseList, Health, ErrorBody, ErrorEnvelope, ScoreSource and ServerErrorCode.
  Public decodeTransaction/decodeRiskAssessment/decodeCaseSummary/decodeCaseDetail/
  decodeCaseList/decodeHealth/decodeErrorEnvelope accept unknown and return checked
  copies. ErrorBody is checked within its envelope. No unchecked type casts occur.
- Required own keys and exact key sets enforce all nested closed objects. Values
  are not coerced: strict string/number types, finite scores [0,1], allowed sources,
  strict ID/decimal/currency patterns and Unicode code point length bounds.
  Empty lists remain successful; malformed lists are never converted to empty.
- UTC timestamps require strict Z and actual Gregorian dates/time fields.
  Fractional seconds/lowercase t are accepted, matching the existing backend.
  Years 0001–9999 and seconds 00–59 follow its format checker. Calendar checks
  reject impossible dates that Date.parse would normalize.
- Detail decoding rejects transaction/assessment identity mismatch. Canonical
  fields contain no evaluation labels, unknown fields or invented risk categories.
- Every 200 response is decoded. Requests require application/json (parameters
  accepted); broken JSON, wrong media types, undocumented statuses and status/code
  disagreement become invalid_response. 404/422/500 envelopes are decoded and
  mapped to controlled codes/statuses. Arbitrary server messages are discarded.

## Timeout and cancellation

A per-request AbortController and 5000 ms timer cover fetch and JSON body reading.
The caller signal forwards cancellation without modifying that signal. An
already-aborted signal rejects before fetching. First interruption determines
timeout versus cancelled; transport failures use network_error. A TypeError from
body reading also represents a failed stream; malformed JSON is invalid_response.

An explicit promise race rejects promptly even if transport/body ignores abort;
late completion cannot change the settled result. Finally removes the timer and
caller listener on success, HTTP/validation/network failure, cancellation or timeout.
Stale view selection handling still belongs to T018.
